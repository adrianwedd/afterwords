## Behaviour and compatibility dependency

The provider requires the serving profile's explicit `{voice}`. No fallback to
another profile, `.afterwords` or server default is permitted. Native gateway
replies, including cleared-platform replies, produce complete synchronous
artifacts and archive below `gateway-delivered`, outside feed polling. Native
local consumers use `consumer-delivered`; ordinary CLI tools retain provider
playback and their own profile archive. Surviving partial audio is retained with
a nonzero result; no usable audio leaves no output. Canonical chunking and the
Markdown newline fix are retained. Loopback port validation remains fail closed.

Profile-wide playback ownership was insufficient: installed Hermes' actual
native consumer lacked the shared mute/lease guards. The hash-bound companion
patch in `hermes/patches/` scopes synthesis ownership using a ContextVar and
applies mute/shared locking in the real native sentence consumer and both CLI
fallback consumers. It is staged and tested, **not installed or claimed active**.
Separate M5 and Studio manifests bind their different installed source revisions.
The preparation tool refuses drifted source. This dependency must be installed
before switching canonical Afterwords source to the candidate. A legacy
`AFTERWORDS_PLAYBACK_OWNER=hermes` command setting is accepted for compatibility
but does not silence ordinary tool callers. Native caller identity is per call.
