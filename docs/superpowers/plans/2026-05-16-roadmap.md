# Afterwords roadmap (4 phases) + Sprint 1 plan

**Date:** 2026-05-16
**Owner:** @adrianwedd
**Status:** Sprint 1 ready to execute

## Roadmap

Sequenced, not parallel. Each phase has an explicit exit criterion. When a phase
exits, re-brainstorm the next one with whatever was learned before opening the
detailed task list.

### Phase 1 — Server v1 (this sprint)

Close out the cloning-fidelity work from issue #14, ship the MFCC regression
test (#70), restore the Backend Comparison docs section, and tag `v1.0.0`. The
goal is a stable, documented local server with no open correctness questions
about its four cloning backends.

**Exit criterion:** `pytest` green; the 3 flagship voices (galadriel, picard,
attenborough) listen-confirmed on Chatterbox and VoxCPM (Qwen3 0.6B/1.7B are
already confirmed by PRs #10/#11); the 4 deferred trim-threshold voices
(clara-oswald, gulley, loki, the-doctor) either fixed or marked WONTFIX;
`pytest -m integration tests/test_fidelity.py` runs locally; `v1.0.0` tag
pushed; CHANGELOG entry and GitHub release published. Other ~90 Qwen3-only
voices are not gating — they ride along with the existing Qwen3 confidence.

### Phase 2 — Menubar v1 (`afterwords-app`)

Move to the separate `afterwords-app` repo. Phase 1 runtime QA against a live
server, then Phase 2 features (voice list window, port override, autostart
toggle), then Phase 3 release work (code signing, notarization, DMG, Sparkle
auto-updates).

**Exit criterion:** a signed `.app` distributable installs cleanly on a second
machine; the auto-update channel pulls a dev release successfully.

### Phase 3 — Cloud v0 (`afterwords-cloud`)

Re-brainstorm the committed cloud design with lessons from Phases 1–2 baked in,
then ship the first thin slice: auth + proxy to a hosted afterwords instance +
per-user voice storage. Deliberately minimal — no billing, no multi-tenant
GPU pool, no voice marketplace.

**Exit criterion:** a user other than the owner can sign up and synthesize via
a hosted URL.

### Phase 4 — Mixed cleanup

Drain the backlog accumulated during Phases 1–3. Concrete items currently
queued: voice-assignment dedup across `~/repos/*/.afterwords`, hot-reload
removal semantics, and any small wins surfaced during menubar/cloud work.

### Sequencing notes

- Tasks 1, 2, 3 require a running server (`afterwords start`) and headphones.
  Batch them in one listen-test session.
- Task 4 (MFCC test) is independent and can be implemented before or after the
  listen-tests, but its threshold calibration depends on task 1/2 findings —
  start the test scaffolding early, calibrate after listen-tests.
- Tasks 5 and 6 are docs-only; do them after 1–4 so they reflect final state.
- Task 7 is the gate. Do not tag until 1–6 are complete and `pytest` is green.

### Out of scope (deferred to Phase 4)

- **Voice-assignment dedup** across `~/repos/*/.afterwords` (~23 galadriel + 7
  other duplicates per memory). Not user-facing; doesn't block a v1 tag.
- **Hot-reload removal semantics.** `POST /reload` is add-only today;
  `DELETE /session/{id}` or restart is required to remove voices. Current
  workflow tolerates this; revisit when cloud needs runtime voice eviction.
- **New backends, new languages, performance work.** No new feature surface in
  v1.

### Backlog (one line each, with reason)

- Voice-assignment dedup — cleanup, no user impact.
- Hot-reload remove semantics — niche; revisit with cloud requirements.
- Per-backend MFCC thresholds — only if the single threshold from #70 proves
  too coarse.
- Backend Comparison audio samples on the demo site — depends on Phase 1
  listen-tests; nice-to-have, not blocking.
