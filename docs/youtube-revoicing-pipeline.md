## Overview

The 69 videos on the channel were generated by NotebookLM Studio — they are not Adrian's voice and contain a meaningful number of factual hallucinations (names, statistics, technical details). The goal is to:

1. Transcribe the NLM audio to get word-level timestamps
2. QA each transcript against its source blog post / project page
3. Use Gemini to produce corrected synthesis scripts and proposed blog post revisions
4. Record a reference WAV of Adrian's voice
5. Clone the voice with Qwen3-TTS (via Afterwords / `clone-voice.sh`)
6. Synthesise the corrected scripts and re-upload

**Corpus stats:**

| Metric | Value |
|--------|-------|
| Videos | 69 |
| Total transcribed words | 47,587 |
| Total audio duration | ~5.3 hours |
| Average video length | ~4.6 minutes |
| QA'd videos | 55 (of 69) |
| Videos with QA issues | 54 |
| Videos QA'd clean | 0 (preliminary — all have at least one NLM confabulation) |
| Content review files | 57 (of 72 blog posts + projects) |
| Posts needing revision | 41 |
| Posts reviewed as OK | 16 |
| Synthesis scripts generated | 57 (~343 words avg, ~2.5 min spoken) |

## Stage 1 — Transcription

### Tools

| Tool | Version | Role |
|------|---------|------|
| `yt-dlp` | 2026.03.17 | Audio download |
| `ffmpeg` | 8.1.1 | Normalise to 16kHz mono WAV |
| `parakeet-tdt-0.6b-v2` | via mlx-audio | Transcription |
| `scripts/transcribe.py` | — | Single-file transcription |
| `scripts/transcribe-youtube-batch.sh` | — | Batch pipeline |

### Backend choice: parakeet over faster-whisper

The pipeline uses parakeet (Metal-native, Apple Silicon) rather than faster-whisper. Benchmark on 5-minute audio:

| Metric | faster-whisper (large-v2) | parakeet-tdt-0.6b-v2 |
|--------|--------------------------|----------------------|
| RTF | ~0.90× | **~0.02×** |
| Elapsed (5 min audio) | ~4.5 min | **~6 sec** |
| Transcript similarity | — | 98.7% agreement with whisper |
| Mean timestamp drift | — | 0.08 s |

At RTF 0.02×, the entire 5.3-hour corpus was transcribed in under 8 minutes.

### Output format

Each `transcripts/youtube/<video_id>.json` is an array of word objects:

```json
[
  {"word": "If",    "start": 0.24, "end": 0.48},
  {"word": "you",   "start": 0.48, "end": 0.64},
  {"word": "walk",  "start": 0.64, "end": 0.96},
  ...
]
```

Times are in seconds. Words are stripped of leading/trailing whitespace; punctuation is attached to the word token (e.g. `"club,"`).

### Parakeet token merging

Parakeet outputs sub-word tokens with leading spaces as word-boundary markers (e.g. `' L'`, `'o'`, `'ok'` for "Look"). The `_merge_parakeet_tokens()` function in `scripts/transcribe.py` merges these into whole words before writing JSON.

### Running the batch

```bash
cd /path/to/afterwords

# Single video
./scripts/transcribe-youtube-batch.sh <VIDEO_ID>

# Full batch (all IDs from summary at end of this doc)
./scripts/transcribe-youtube-batch.sh ID1 ID2 ID3 ...

# Resume (already-done IDs are skipped automatically)
./scripts/transcribe-youtube-batch.sh $(cat video-ids.txt)
```

## Stage 2 — Transcript QA

### Purpose

NLM hallucinates plausible-sounding details. Every video transcript is QA'd against its source content (blog post and/or project markdown) by Gemini to flag:

- Wrong names or spellings (e.g. "Seamus and Mikawai" → "Shamus and Nicolai")
- Wrong statistics, dates, or version numbers
- Invented UI flows or technical details not in the source
- Misattributed quotes or context
- Generic filler that contradicts the actual source

**Result: 54 of 55 QA'd videos have at least one issue.** Zero videos are fully clean.

### Sample issues found

**Auditory Spiral** — DJ name corrupted:
> ISSUE at ~1:34: "DJs Seamus and Mikawai"
> SOURCE SAYS: "DJ Shamus (Shane) and Nicolai"
> REPLACEMENT: "DJs Shamus and Nicolai"

**Afterwords** — project name misread:
> ISSUE at ~0:00: "clawed code transcribes every word you say"
> SOURCE SAYS: "Claude Code already listens"
> REPLACEMENT: "Claude Code transcribes your spoken words"

**Before the Words Existed** — wrong DSM edition/date:
> ISSUE at ~0s: "the American Psychiatric Association officially released the third edition of its diagnostic manual, the DSM-3"
> SOURCE SAYS: "In 1984, the DSM-III categorised ADD as a childhood disorder"
> REPLACEMENT: "the DSM-III categorized attention deficit disorder as a childhood disorder"

**Zero-Build Web Development** — project name split wrong:
> ISSUE at ~0:21: "Consider the WolfClan martial arts operations platform"
> SOURCE SAYS: "Wolf Clan" (two words)
> REPLACEMENT: "Consider the Wolf Clan martial arts operations platform"

**When AI Systems Talk** — invented project name:
> ISSUE at ~0:46: "Recent research out of the Maltbook project"
> SOURCE SAYS: (not mentioned — fully fabricated)

## Stage 3 — Content Review & Synthesis Scripts

### Purpose

Beyond just QA-ing the audio, this stage reviews every blog post and project page against:

1. The source GitHub repo README (fetched live via `gh api`)
2. Existing QA notes (hallucinations already identified)

And produces two outputs per item:

**A) Blog post revision suggestions** — specific diffs (CHANGE / TO / REASON) for the markdown source.

**B) Synthesis script** — a complete 350–550 word narration script written for TTS:
  - Second-person conversational prose
  - No markdown, bullets, or headers
  - Factually grounded in source only
  - Ends with a call to action to the site

### Sample synthesis script (Afterwords)

> Claude Code already transcribes your spoken words. But until now, it always responded as silent characters on a dark terminal. You speak to it, and it types back. Afterwords was built to close this loop. It intercepts every Claude Code response, sends the text to a local text-to-speech server, and plays it through your speakers, creating a real two-way voice conversation that runs entirely on your machine.
>
> Traditionally, high-quality voice synthesis required cloud-based infrastructure and an internet connection, which introduced latency and privacy concerns. This dynamic changes with Apple Silicon. Afterwords leverages this by running the Qwen3-TTS engine on Apple's MLX framework, utilising the unified memory architecture of the M1 chip, at the exact moment Claude Code finishes a thought.
>
> You get over one hundred cloned voices, ranging from famous actors and characters to science communicators, all extracted from fifteen-second clips. Because it uses zero-shot cloning, adding a new voice just takes a small reference file, costing zero additional memory regardless of how many voices you have. [...]

### Running the review

```bash
cd /path/to/afterwords

# One slug (matches blog or project filename stem)
python3 scripts/review-content.py afterwords

# All (skips already-done)
python3 scripts/review-content.py

# List all items with their repo URLs
python3 scripts/review-content.py --list
```

Model used: `gemini-3.1-flash-lite-preview` (fast, sufficient for factual QA and prose generation at this scale).

### Output location

`transcripts/review/<slug>.md` — one file per blog post or project. Slug is the markdown filename stem with `-post` suffix removed.

## Stage 4 — Reference WAV & Voice Cloning

### Why a reference WAV

Qwen3-TTS uses zero-shot voice cloning from a short reference audio clip (~15 seconds). The reference WAV determines the voice, accent, and prosody of the synthesised audio. Recording Adrian's voice once produces all 69 video narrations.

**Critically**, the reference WAV should contain words that Qwen3-TTS is likely to mispronounce (see [Mispronunciation Shortlist](#mispronunciation-shortlist) below), so the model can learn the correct phonetics from the reference rather than guessing.

### Voice cloning command

```bash
cd /path/to/afterwords

# Clone voice from a WAV file
./clone-voice.sh --name "adrian" --file /path/to/reference.wav

# Or from a YouTube clip (15–30 sec segment works well)
afterwords clone --name "adrian" --youtube "URL" --start 10 --duration 20
```

### Synthesising a script

```bash
# Synthesise one script
afterwords speak --voice adrian \
  "$(cat transcripts/review/afterwords.md | sed -n '/### B) SYNTHESIS SCRIPT/,$ p' | tail -n +2)"

# Or pipe to the server directly
curl -s http://localhost:8000/synthesise \
  -H "Content-Type: application/json" \
  -d '{"text": "...", "voice": "adrian"}' \
  --output afterwords-narration.wav
```

## Reference WAV Recording Guide

### Goal

A single ~60-second clean recording of Adrian's natural speaking voice. The reference does not need to include every word from the shortlist — the zero-shot cloning works from prosody and timbre, not phoneme-by-phoneme mapping. However, including problem words in the reference gives the TTS a direct phonetic anchor.

### Recommended script for the reference recording

Read this naturally, at your normal podcast pace. No need to over-enunciate:

> "Hi, I'm Adrian Wedd — adrianwedd dot com. I work on AI safety, voice cloning, and local tooling for Apple Silicon.
>
> Some of the tools I use: MLX — that's em-el-ex — Apple's machine learning framework. Qwen3, the language model — pronounced chwen-three. Ollama — oh-LAH-ma. And Afterwords — after-words, not afterwards — my local TTS bridge for Claude Code.
>
> Projects include Afterglow, Orbitr, Dx0 — dee-ex-zero — and RTRFM, Perth's community radio station — ar-tee-ar-ef-em.
>
> Techniques: EMDR — ee-em-dee-ar. RAG pipelines. RLHF and RLAIF training. BM25 ranking. NeurIPS — noor-ips — and ICLR research.
>
> The goal is to build tools that are honest, local, and yours."

**Recording requirements:**

| Parameter | Requirement |
|-----------|-------------|
| Format | WAV, 44.1 kHz or 48 kHz, mono |
| Duration | 15–90 seconds (15s minimum for cloning) |
| Environment | Quiet room, no reverb |
| Mic | Any decent mic — the MacBook mic works if there's no background noise |
| Breath | Natural pauses are fine; avoid clipping or distortion |

**To record from terminal:**

```bash
# macOS — record 60 seconds to reference.wav
sox -d -r 44100 -c 1 reference.wav trim 0 60

# Or use QuickTime Player → File → New Audio Recording → save as WAV
```

### After recording

```bash
cd /path/to/afterwords

# Clone the voice
./clone-voice.sh --name "adrian-wedd" --file reference.wav

# Verify it sounds right
afterwords speak --voice "adrian-wedd" \
  "This is Adrian Wedd. Afterwords is running on MLX with Qwen3-TTS."
```

## Scripts Reference

All scripts live in `/path/to/afterwords/scripts/`.

### `transcribe.py`

Single-file transcription to word-level JSON.

```
Usage: python scripts/transcribe.py <audio> [options]

Options:
  --backend {faster-whisper,parakeet}   default: faster-whisper
  --model MODEL                         whisper model name (default: large-v2)
  --out FILE                            output JSON (default: stdout)
  --stats                               print RTF and word count to stderr
```

### `transcribe-youtube-batch.sh`

Batch download + transcribe for YouTube video IDs.

```
Usage: ./scripts/transcribe-youtube-batch.sh VIDEO_ID [VIDEO_ID ...]

Output: transcripts/youtube/<id>.json
Skips:  IDs that already have a transcript file
Deps:   yt-dlp, ffmpeg, afterwords .venv with mlx-audio
```

### `compare-transcription.py`

Benchmark faster-whisper vs parakeet on the same audio.

```
Usage:
  python scripts/compare-transcription.py audio.wav
  python scripts/compare-transcription.py --youtube URL [--duration 60]

Reports: RTF, word count, WER (bidirectional), timestamp drift, side-by-side
```

### `qa-transcripts.py`

Gemini-powered QA of NLM transcripts against source content.

```
Usage:
  python scripts/qa-transcripts.py                 # all videos
  python scripts/qa-transcripts.py VIDEO_ID ...    # specific IDs
  python scripts/qa-transcripts.py --list          # show mapping

Output:  transcripts/qa/<video_id>.txt
Model:   gemini (default model, no flag)
Skips:   already-QA'd files
```

**Video → source content mapping** is defined in `CONTENT_MAP` inside the script. Each entry maps a YouTube video title to one or more markdown files in `adrianwedd.com/src/content/`.

### `review-content.py`

Gemini content review: blog post revisions + synthesis scripts.

```
Usage:
  python scripts/review-content.py                 # all 72 items
  python scripts/review-content.py SLUG ...        # specific slugs
  python scripts/review-content.py --list          # show items + repos

Output:  transcripts/review/<slug>.md
Model:   gemini-3.1-flash-lite-preview
Skips:   already-reviewed files
Fetches: repo README via `gh api repos/<nwo>/readme`
```

Each output file contains:
- **Section A:** Blog post revision diffs (CHANGE / TO / REASON)
- **Section B:** Complete synthesis script (~350–550 words)
